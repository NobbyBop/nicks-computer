Experiment No. 2: Dynamically Building List of Works

Assuming you are on this page, you likely navigated to it using the table of works on the main page (how convenient!). After writing two works, I decided I would not want to be manually updating this table every time I add one. So, I thought I would add another pre-commit step and use Python once more to dynamically generate the table based on the works in the repository root.

You can check out the whole script here: [view on GitHub]

The task was not super complex, especially after working with HTML injection in my first experiment

I enforced a very simple (and likely to change) naming convention so I can capture the works: type-mmddyyy-title_with_underscores.html. I really only need to know those three things, the title, date, and "type". I already don't know the difference between types. Whether something is an Experiment, Project, or Blog is just going to come down to my vibes-based decision. In the code, I just check the root directory for files with that naming convention and parse them into objects, like the shape below.

{ filename: str, title: str, date: Date, type: str }

The most interesting part of it was getting back into custom comparitors. These allow you to sort elements of lists of any type. Also, you'll notice the Date type above. In the spirit of making thigs ad-hoc, I wrote my own Date class and custom comparitor to go along with it. I didn't feel like getting into the nitty-gritty of dealing with Python's datetime module, and since this use case is so simple I figured I would write it myself.

class Date: def __init__(self, m, d, y): self.m = m self.d = d self.y = y def toStr(self): return f"{self.m}-{self.d}-{self.y}" def compareWorksByDate(work1, work2): """ Compares the works by their date attribute. """ a = work1["date"] b = work2["date"] if a.y > b.y: return -1 if a.y < b.y: return 1 if a.m > b.m: return -1 if a.m < b.m: return 1 if a.d > b.d: return -1 if a.d < b.d: return 1 return 0

Then, it is as simple as works = sorted(works, key=cmp_to_key(compareWorksByDate)) to get a list of the works in order. Doing this took me back to a few of my college classes, and reminded me of my earlier experience with Java (whose classes I greatly prefer over Python's). I used a very similar technique to find and inject the table into the main page as I did last time, so no need to elaborate on that here (plus you can look at the code if you want to know).

As I am piecing together this website, I am writing about building it. What is this website other than a report on how it is built? But I am a big fan of that idea. As I build, I learn and I write. The website takes on a meta, fourth-wall-breaking identity. This experiment in particular really speaks to what I am trying to accomplish. Though small, and though I am re-inventing the wheel in a sense, I am practicing self-reliance on my own ability to plan, code, and communicate. And also I just think it's fun :P

Anyway, to get this set up in my exising GitHub workflow, I added the following 2 lines to .git/hooks/precommit:

python ./scripts/build-table/build-table.py git add ./index.html

And that about does it. (If you read this far, looks like it probably worked!)
